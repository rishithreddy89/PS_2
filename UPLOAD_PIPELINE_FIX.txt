## Document Upload & Embedding Pipeline - Debug & Fix Summary

### Problem Statement
1. Upload succeeded (HTTP 201) but ingestion still called OpenAI API
2. Upload failed due to OpenAI quota exceeded
3. DOCX parsing failed (python-docx not installed)
4. Documents not completely processed or indexed

### Solution Overview
Replaced OpenAI embeddings with local sentence-transformers model (all-MiniLM-L6-v2) to:
- Eliminate external API calls during upload
- Work completely offline
- Process documents locally
- Never hit OpenAI quota limits

---

## Changes Made

### 1. Created Local Embedding Service
**File:** `app/knowledge/local_embedding.py` (NEW)
- Uses `sentence-transformers` library with model `all-MiniLM-L6-v2`
- Generates 384-dimensional embeddings (vs 1536 for OpenAI)
- Runs asynchronously using thread pool
- Singleton pattern for model reuse
- **Key feature:** No external API calls

### 2. Updated Ingestion Service
**File:** `app/knowledge/ingestion.py`
- **Changed:** `from app.knowledge.embedding import get_embedding_service` → `from app.knowledge.local_embedding import get_local_embedding_service`
- **Changed:** `self.embedding_service = get_embedding_service()` → `self.embedding_service = get_local_embedding_service()`
- **Fixed:** DOCX parsing error handling - now raises ImportError with clear message instead of silently skipping

### 3. Updated Retrieval Service
**File:** `app/knowledge/retrieval.py`
- **Changed:** Uses `get_local_embedding_service()` instead of `get_embedding_service()`

- Works with 384-dimensional embeddings from local model

### 4. Enhanced Document Upload Router

## Upload Pipeline (After Fix)

```
Client                    Backend
  |                          |
  ├─ POST /upload ─────────→ |
  |                          ├─ Validate file
  |                          ├─ Save file to disk
  |                          ├─ Create DB record (status: processing)
  |                          ├─ Parse document (DOCX/PDF/TXT/MD)
  |                          ├─ Chunk text (512 chars, 50 char overlap)
  |                          ├─ Generate embeddings (LOCAL - no API!)
  |                          ├─ Store in ChromaDB
  |                          ├─ Update DB record (status: indexed)
  |                          ├─ 201 Created ─────────→ |
  |                          |
  └─ GET /list ─────────────→ |
     (every 3 sec)            ├─ Return documents with status
                              └─ JSON ────────→ |
```

## Installation & Setup

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

This installs:
- `sentence-transformers` - Local embedding model
- `torch` - ML framework for sentence-transformers
- `python-docx` - DOCX parsing
- All other required packages

### 2. Configure Environment
```bash
cp .env.example .env
# Already configured for local embeddings:
# EMBEDDING_MODEL=all-MiniLM-L6-v2
# VECTOR_DB_DIMENSION=384
```

### 3. Start Backend
```bash
poetry run uvicorn app.main:app --reload
```

First startup will download the embedding model (~60MB) - this is a one-time operation.

### 4. Verify Installation
```bash
python verify_local_embeddings.py
```

Monitor the backend logs - should see ZERO requests to `api.openai.com`

## Troubleshooting

### Issue: "python-docx not installed"
**Solution:** Run `pip install python-docx`

### Issue: "sentence-transformers not installed"
**Solution:** Run `pip install sentence-transformers torch`

### Issue: Model takes long to download
**Solution:** Normal - ~60MB one-time download on first run. Cached after that.

### Issue: Slow embedding generation
**Solution:** Runs on CPU by default. Large documents may take a few seconds.

### Issue: High memory usage
**Solution:** Model uses ~400MB RAM when loaded. Normal for local ML.

## Performance Characteristics

### Embedding Generation
- **Speed:** ~100-200 texts/second (CPU)
- **Memory:** ~400MB model + processing buffer
- **Dimension:** 384 (vs 1536 for OpenAI)
- **Cost:** $0 (fully local)

### Document Processing (example)
- Upload: 100ms
- Parse DOCX: 50-200ms
- Chunking: 10-50ms
