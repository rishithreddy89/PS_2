## Migration Guide: OpenAI Embeddings → Local Embeddings

### Current Status (AFTER FIX)

#### ✅ ACTIVE - Use These
- `app.knowledge.local_embedding.LocalEmbeddingService` - **USE THIS**
- `app.knowledge.local_embedding.get_local_embedding_service()` - **USE THIS**
- All document ingestion uses local embeddings
- All retrieval uses local embeddings

#### ⚠️ DEPRECATED - Don't Use for New Code
- `app.knowledge.embedding.EmbeddingService` - Kept for compatibility only
- `app.knowledge.embedding.get_embedding_service()` - Don't use

## Code Examples

### ✅ CORRECT - Using Local Embeddings

```python
from app.knowledge.local_embedding import get_local_embedding_service

# Get service
embedding_service = get_local_embedding_service()

# Generate single embedding
embedding = await embedding_service.embed_text("legal document text")

# Generate batch embeddings
embeddings = await embedding_service.embed_batch([
    "document 1",
    "document 2",
    "document 3"
])

# Generate query embedding
query_embedding = await embedding_service.embed_query("search query")
```

### ❌ WRONG - Using Old OpenAI Embeddings

```python
# DON'T DO THIS - kept for backward compatibility only
from app.knowledge.embedding import get_embedding_service

embedding_service = get_embedding_service()  # Requires OpenAI API key!
embedding = await embedding_service.embed_text("...")  # Calls openai.com API
```

## Vector Dimensions

### Local Model: `all-MiniLM-L6-v2`
- **Dimension:** 384
- **Size:** ~60MB
- **Speed:** Fast CPU inference
- **Quality:** Good for semantic search
- **Cost:** Free, offline

### OpenAI: `text-embedding-3-small`
- **Dimension:** 1536
- **Size:** N/A (cloud-hosted)
- **Speed:** Fast (network latency)
- **Quality:** Excellent
- **Cost:** $0.02 per 1M tokens

### Important: ChromaDB Collections
Existing collections with 1536 dimensions need migration if you want to reuse:
```python
# To handle different dimensions:
if embedding_dim == 384:  # Local model
    use_local_collection()
elif embedding_dim == 1536:  # OpenAI model
    use_openai_collection()
```

Fresh ChromaDB collections are auto-created with correct dimensions.

## What Changed in Core Services

### Document Ingestion Flow
```
BEFORE:
Upload → Save → Parse → Chunk → OpenAI API (calls openai.com) → ChromaDB → DB

AFTER:
Upload → Save → Parse → Chunk → Local Embedding (no API) → ChromaDB → DB
```

### Why This Matters
- **No API Calls:** Upload works offline
- **No Rate Limits:** Can process unlimited documents
- **No Quota:** Never hits OpenAI limits
- **No Latency:** Embedding runs on server CPU
- **No Costs:** Free embedding generation

## Troubleshooting

### "Module not found: sentence_transformers"
```bash
pip install sentence-transformers torch
```

### "CUDA out of memory"
The model runs on CPU by default (no GPU needed).
If you have GPU and want to use it:
```python
# Modify local_embedding.py
self.model = SentenceTransformer(model_name, device='cuda')
```

### "python-docx not installed"
```bash
pip install python-docx
```

### Model too slow
First run downloads the model (~60MB). Subsequent runs use cached model.
Processing speed: ~100-200 texts/second on modern CPU.

### High memory usage
Model uses ~400MB RAM when loaded (normal for ML models).
